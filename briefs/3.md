# Termora — UI/UX ve Tasarım Sistemi Brief’i: Bölüm 3

## Tasarım Hedefi

Termora; hızlı, odaklı ve profesyonel hissettiren native bir macOS terminali olmalıdır.

Arayüzün amacı kullanıcıya kendini göstermek değil, terminal kullanımını kolaylaştırmaktır. Terminal alanı her zaman uygulamanın ana odağı olarak kalmalıdır.

Temel his:

- Native
- Hızlı
- Sade
- Güçlü
- Klavye odaklı
- Gereksiz dikkat dağıtıcılardan uzak

## Tasarım İlkeleri

### Terminal Önceliklidir

Araç çubukları ve paneller terminal alanını gereksiz yere küçültmemelidir.

### Native macOS Deneyimi

- Standart macOS pencere davranışları korunmalı
- SF Symbols kullanılmalı
- Sistem menüleri desteklenmeli
- Sağ tık menüleri doğal çalışmalı
- Sistem açık ve koyu tema tercihleri izlenmeli
- Vibrancy yalnızca gerekli alanlarda kullanılmalı

### Klavye Öncelikli Kullanım

Her temel işlem klavye kısayoluna sahip olmalıdır. Fare, zorunluluk değil alternatif olmalıdır.

### Aşamalı Karmaşıklık

Yeni kullanıcı yalnızca terminali görmelidir. Workspace, SSH, Docker ve AI özellikleri ihtiyaç duyulduğunda açılmalıdır.

## Marka Kimliği

- Soyut bir `T` harfi
- Komut yönünü çağrıştıran geometrik geçiş
- Elektrik mavisi ve mor gradyan
- Gece laciverti arka plan

Logo arayüz içinde sık tekrarlanmamalıdır. Ağırlıklı olarak uygulama ikonu, onboarding ve About ekranında kullanılmalıdır.

## Ana Pencere Yapısı

Ana pencere şu katmanlardan oluşmalıdır:

```text
Title Bar
Tab Bar
Terminal Workspace
Optional Side Panel
Optional Status Bar
```

### Title Bar

Title bar yüksekliği native macOS ölçülerine yakın tutulmalıdır.

İçerik:

- Trafik ışığı kontrolleri
- Aktif workspace adı
- Komut paleti butonu
- İsteğe bağlı sidebar butonu
- AI paneli butonu

Title bar sürüklenebilir olmalıdır.

### Tab Bar

Her sekmede:

- Çalışan işlem ikonu
- Sekme başlığı
- Değişiklik veya aktivite göstergesi
- Kapatma butonu

Sekme başlığı öncelik sırası:

1. Kullanıcının verdiği özel isim
2. Çalışan foreground işlem
3. Aktif klasör
4. Shell adı

Aktif sekmenin altında ince mavi-mor vurgu kullanılabilir.

Sekmeler sürüklenerek sıralanabilmelidir.

### Terminal Workspace

Terminal alanı:

- Gereksiz padding içermemeli
- Aktif paneli ince bir border ile göstermeli
- Split divider alanları kolay tutulabilir olmalı
- Text selection görünür olmalı
- Scrollbar macOS davranışını izlemeli

### Status Bar

Status bar varsayılan olarak sade tutulmalı ve kapatılabilmelidir.

Gösterilebilecek bilgiler:

- Aktif shell
- Çalışma dizini
- Git branch
- SSH bağlantısı
- Çıkış kodu
- Terminal ölçüsü
- AI veya gizlilik durumu

## Sidebar

Sidebar varsayılan olarak kapalı olabilir.

Bölümler:

- Workspaces
- Recent Folders
- SSH Hosts
- Docker
- Saved Commands

Sidebar genişliği:

- Minimum: 220 pt
- Varsayılan: 260 pt
- Maksimum: 380 pt

Sidebar daraltıldığında yalnızca ikon görünümüne geçmemeli; tamamen kapanmalıdır. Terminalin yanına anlamsız bir ikon şeridi bırakılmamalıdır.

## Yeni Sekme Ekranı

Yeni sekme açıldığında shell doğrudan başlatılmalıdır.

Kullanıcı özel bir launcher ekranı tercih ederse şu seçenekler gösterilebilir:

- Default Shell
- Open Folder
- Open Workspace
- Connect SSH
- Recent Sessions

Bu ekran terminal kullanımını yavaşlatmamalı ve ayarlardan kapatılabilmelidir.

## Split Terminal Deneyimi

Terminal aşağıdaki yönlerde bölünebilmelidir:

- Dikey
- Yatay

Aktif panel:

- İnce accent border
- Hafif arka plan farkı
- Aktif başlık göstergesi

Panel kontrolleri sürekli görünmemeli; panel üzerine gelindiğinde gösterilmelidir.

Split kapatıldığında yalnızca ilgili terminal oturumu kapatılmalıdır.

Çalışan işlem varsa kullanıcı uyarılmalıdır.

## Komut Paleti Tasarımı

Komut paleti pencerenin üst orta bölümünde açılmalıdır.

Özellikler:

- Maksimum genişlik: 640 pt
- Arka plan blur
- Hızlı fuzzy search
- Klavye ile tam kontrol
- Son kullanılan komutlar
- Kategori ikonları
- Kısayol bilgileri

Sonuç kategorileri:

- Actions
- Workspaces
- Folders
- SSH
- Settings
- Themes
- AI Actions

Komut paleti açıldığında terminal oturumu durmamalıdır.

## AI Paneli

AI paneli sağ taraftan açılmalıdır.

Varsayılan genişlik:

```text
360–420 pt
```

Panel bölümleri:

1. Konuşma başlığı
2. Mesaj geçmişi
3. Gönderilecek bağlam göstergesi
4. Prompt giriş alanı
5. Sağlayıcı ve model seçimi

Üretilen shell komutlarında şu eylemler bulunmalıdır:

- Copy
- Insert
- Explain
- Run

`Run` işlemi kullanıcı onayı olmadan çalışmamalıdır.

Riskli komutlarda kırmızı uyarı alanı gösterilmelidir.

## SSH Ekranı

SSH bağlantıları sidebar veya komut paleti üzerinden açılabilmelidir.

Liste öğesinde:

- Sunucu adı
- Host
- Kullanıcı
- Durum
- Etiket
- Son bağlantı zamanı

Bağlantı durumları:

- Disconnected
- Connecting
- Connected
- Failed

Sunucu kartları aşırı büyük tasarlanmamalıdır. Yoğun bilgi gösteren kompakt liste tercih edilmelidir.

## Workspace Ekranı

Workspace kartında:

- Workspace adı
- Proje yolu
- Sekme sayısı
- Son açılma zamanı
- Git repository bilgisi
- Başlatma butonu

Yeni workspace oluştururken kullanıcı:

1. Proje klasörünü seçer
2. Terminal düzenini belirler
3. Başlangıç komutlarını ekler
4. Workspace’i kaydeder

Gelişmiş ayarlar ilk ekranda gösterilmemelidir.

Sol menü:

- General

## Durum Tasarımları

### Empty State

Boş ekranlarda:

- Tek cümlelik açıklama
- Birincil eylem
- Gerekirse klavye kısayolu

Gereksiz illüstrasyon kullanılmamalıdır.

### Loading State

Terminal açılışında uzun skeleton animasyonları gösterilmemelidir. Shell birkaç yüz milisaniye içinde başlamıyorsa küçük bir durum göstergesi yeterlidir.

### Error State

Hata mesajı şunları açıklamalıdır:

- Ne başarısız oldu?
- Muhtemel sebep nedir?
- Kullanıcı ne yapabilir?
- Teknik detay nasıl görüntülenir?

Örnek:

```text
Shell başlatılamadı

/usr/local/bin/fish dosyası bulunamadı.
Varsayılan shell ayarını kontrol edin.

[Shell Ayarlarını Aç] [Tekrar Dene]
```

## Animasyonlar

Animasyon süresi çoğunlukla `120–180 ms` arasında tutulmalıdır.

Animasyon uygulanabilecek alanlar:

- Sidebar açılışı
- AI paneli açılışı
- Komut paleti
- Sekme değişimi
- Hover durumları

Terminal metnine, cursor hareketine veya terminal çıktısına dekoratif animasyon uygulanmamalıdır.

Sistem “Reduce Motion” ayarı desteklenmelidir.

## Ses Kullanımı

Uygulama varsayılan olarak sessiz olmalıdır.

İsteğe bağlı sesler:

- Terminal bell
- Uzun işlem tamamlandı
- SSH bağlantısı koptu
- Kritik hata

Her ses ayrı ayrı kapatılabilmelidir.

## Küçük Pencere Davranışı

Pencere daraldığında:

1. Status bar bilgileri azaltılmalı
2. Sekme başlıkları kısaltılmalı
3. Toolbar butonları overflow menüsüne alınmalı
4. Sidebar otomatik kapanabilmeli
5. Terminal alanı korunmalı

Minimum pencere boyutu yaklaşık:

```text
720 × 480 pt
```

- Kısa
- Teknik olarak doğru
